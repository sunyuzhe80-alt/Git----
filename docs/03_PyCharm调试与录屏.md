# PyCharm / VS Code 调试与 EV 录屏

视频需要本人实际操作并讲解。项目提供步骤和讲稿，不包含已经录制的视频，不声称已代你完成 IDE Debug。

## 环境准备

1. 用 PyCharm 打开整个 momentum_strategy_py36 文件夹，而不是只打开某个 py 文件。
2. 按 README 用 Anaconda 创建 momentum_py36 环境，在 PyCharm 的 Python Interpreter 中选它的 python.exe。
3. 当前电脑也可选择已验证的 `C:\Users\86198\anaconda3\envs\myEnvironment\python.exe`。名称不重要，关键是实际解释器来自 Anaconda 且可运行。
4. 运行目标为 main.py，首次参数留空，正常运行后打开 outputs/report.html。
5. 若使用 VS Code，选择对应 Python 解释器，再启动“调试 Python 文件”。招聘要求允许 PyCharm 或 VS Code 录制 Debug。

## 先练习一个可手算的小样本

在 tests/test_strategy.py 中看 test_signal_delay_and_first_profit。四股中只有 A 按 1、2、4、8、16 上涨，其余不变，临时使用 1 日动量、选 1 只、成本为 0。

第 2 日收盘产生信号；第 3 日收盘买入，净值仍是 1；第 4 日才变为 2；第 5 日变为 4。这只是解释测试时序，正式策略仍用 20 日、两只股票和成本 0.1%。

## 正式录制建议 7～10 分钟

| 环节 | 操作与讲解 | 时间参考 |
|---|---|---|
| 环境 | 展示 Anaconda 环境、IDE 解释器和文件结构 | 1 分钟 |
| 数据与来源 | 展示 CSV 必要列、参考工具包和来源说明 | 1 分钟 |
| 因子 Debug | 在 rank_momentum 的 scores 和 ordered 行暂停，单步看分数、排名、weights | 2 分钟 |
| 回测 Debug | 在 before、pending 判断、rebalance 调用、value 和日收益行暂停，观察旧持仓、费用、收盘持仓 | 2～3 分钟 |
| 测试与结果 | 展示测试 OK、报告图表，解释跑输基准和回撤 | 1～2 分钟 |

PyCharm 通常 F8 是 Step Over，F7 是 Step Into，F9 是继续，以实际菜单为准。停在某行时通常该行尚未执行，单步后再观察变量。

第一天信号会选 MSFT 和 IBM。继续到 2007-02-02，观察原持仓为 0，买入前没有股票收益，只有买入成本。再到下一个交易日，才观察持仓价格变化。可用条件断点仅在指定日期暂停，避免遍历全部 2306 行。

不要在每一行都设断点；二分法辅助函数只演示前两三步，并说明是在寻找扣费后可用资金，不需要把 80 次循环全部录下来。

## 核心讲稿（理解后用自己的话讲）

“我选择测试一，做一个简单动量选股策略。因子就是分数，这里用过去 20 个交易日的涨跌幅，每隔 5 个交易日选前两只。参考包示例是短期反转和合成数据，我改成真实历史样本上的动量，并独立添加了交易记账。”

“这行只读取今天和 20 个交易日前的价格。同分按股票代码排序。今天的名单存进 pending，明天收盘才成交，不能提前获得买入前的涨幅。”

“每天先按旧持仓估值，再执行昨日名单并扣成本。交易金额包括卖出和买入两侧，调仓后按扣费后的资金等权分配。期间单位数不变，权重自然漂移。”

“默认策略累计收益 161.84%，基准 314.54%；最大回撤 62.89%，比基准更大。说明本样本和参数下没有表现出优势。我没有为了让结果好看而事后更换规则。”

“代码由 AI 辅助编写，我通过小样本测试和逐行调试核对逻辑。数据口径和四股样本存在限制，结果不能证明未来收益。”

最后这句话只在真实完成理解和调试后使用。

## EV 录屏与分享

打开 EV 录屏，选择能看清 IDE 代码、变量和执行行的区域，开启麦克风。先试录 15 秒确认文字清晰、声音正常，再录正式视频。必须实际出现断点暂停和单步执行，单纯展示代码或结果不算 Debug。

保存 MP4 并完整回放，上传百度网盘或飞书。邮件提供可下载链接、提取码和有效期，检查他人可访问，不直接把视频附进邮件。
